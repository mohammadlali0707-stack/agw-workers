### 1. Patch Formulation & Architecture

The offline resilience patch [Reports/audit/gate-webhook-health-resilience.patch](file:///home/runner/work/_temp/agent-repo-43580441155-1-run-agy/Reports/audit/gate-webhook-health-resilience.patch) targets [.github/workflows/gate-webhook-health.yml](file:///home/runner/work/_temp/agent-repo-43580441155-1-run-agy/.github/workflows/gate-webhook-health.yml) with **zero direct modifications** to the live workflow on `main`.

Key architectural enhancements in the patch:
- **Decoupled Exit & HTTP Code Capture:** Replaces the problematic command-substitution fallback (`STATUS=$(curl ... || echo "000")`) with separate, explicit variable assignments (`HTTP_CODE` and `CURL_EXIT`).
- **Elimination of the `'000000'` Defect:** On curl timeout or connection abort, curl's empty or `'000'` output no longer concatenates with subshell `echo "000"`, preventing malformed status strings (`000000` or `000\n000`).
- **Clean Server Failure Routing:** Routes all curl timeouts (`exit 28`), network connection failures (`exit 7`, `exit 6`, `exit 35`), status `000`, and HTTP `5xx` responses directly to `FAIL_TYPE=server_failure` rather than falling through to `config_error`.
- **Fork Label Creation Tolerance:** Inserts `continue-on-error: true` on the alert notification step and adds an exit-guarded, unlabelled fallback with warning redirection (`|| echo "::warning::failed to create alert issue on $REPO..."`) to prevent runner aborts under `set -e` in permission-restricted fork environments.
