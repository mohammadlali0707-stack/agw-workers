### Diagnosis & Root Cause Analysis (Issue #169)

Analysis of the Gate 2 (`gate-webhook-health.yml`) failures across `mohammadlali0707-stack/agw-workers` (runs `43482285448`, `43352031291`, `43313293491`) and `lali94m-max/agw-workers` (run `43316523910`) revealed two cascading defects:

1. **Curl Exit Code Masking & Duplicate `000000` Status Concatenation (Step 3)**:
   - When `curl` encountered a timeout (`--max-time 10`, exit code 28 `CURLE_OPERATION_TIMEDOUT`) or network failure (exit 7 `CURLE_COULDNT_CONNECT`, exit 6 DNS failure), `-w "%{http_code}"` emitted `000` to stdout before terminating with a non-zero exit code.
   - The subshell fallback `|| echo "000"` was executed, writing a second `000` to stdout. Command substitution `$(...)` concatenated these into `STATUS="000000"`.
   - The shell ladder evaluated `[ "$STATUS" = "000" ]` (false) and `[ "$STATUS" -ge 500 ]` (false, as `000000` evaluates to 0 in bash integer comparison; `0 >= 500` is false).
   - Execution fell through to `else`, wrongly setting `FAIL_TYPE=config_error` and `FAIL_MESSAGE="HTTP 000000: Unexpected HTTP response received from webhook endpoint."`, misclassifying network timeouts/server outages as repository webhook configuration errors.
2. **Step 4 Secondary Alert Crash on Fork Checkouts**:
   - Step 4 lacked `continue-on-error: true`.
   - On forks where the GITHUB_TOKEN has read-only permissions or repository issues are disabled, `gh label create alert` and `gh issue create ... --label "alert"` failed. The unlabelled fallback was not fully guarded with warning redirection.
   - Under `set -e`, any non-zero exit terminated the runner, converting an alert notification hiccup into a hard CI crash.
